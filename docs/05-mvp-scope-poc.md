## 3. 기술 검증(PoC) 항목과 결과

### 3.1 브라우저 내 AI 배경 제거: onnxruntime-web WebGPU vs WASM

**결과 요약**: 통과. ISNet general-use ONNX를 웹에서 실사용 시간으로 실행할 수 있고, WebGPU 우선·WASM 폴백 구성으로 확정했다.

**실측 환경**: Chromium 계열 브라우저(버전·GPU 기록 없음), 개발 PC, onnxruntime-web 1.31.1, 테스트 이미지 1104×1428 JPG(밝은 회색 배경 + 흰 옷 인물). 모델 변형: WebGPU는 fp16(약 84MB), WASM은 fp32(약 168MB).

| 측정 항목 | WebGPU | WASM(`crossOriginIsolated` 4스레드) | 비고 |
|---|---|---|---|
| 첫 실행 전체(모델 다운로드 포함) | **8.6초** | **12.2초** | 회선 속도 기록 없음 |
| 이후 실행(모델 로드 후, 장당) | **1.6~1.7초/장** | 미측정 | 같은 이미지, 세션 재사용 상태 |
| 세션 생성·추론·전처리·후처리 개별 시간 | 미측정 | 미측정 | 전체 시간만 `[bg]` 로그(`console.info`)로 확인 |
| WASM 단일 스레드 | — | 미측정 | 비격리 환경은 스레드 1 |
| 입력 2048px / 4000px / 8000px | 미측정 | 미측정 | 대형 입력 한계 미확인 |
| 피크 메모리 | 미측정 | 미측정 | |
| 멀티스레드 조건 | — | 필요: cross-origin isolation | COOP `same-origin` + COEP `credentialless`를 vite dev/preview와 `vercel.json`에 추가 |

**판정 결과**:

| 판정 | 결과 |
|---|---|
| 품질 | 사용자 제보 실패 사례(밝은 회색 배경 인물 + 흰 옷)에서 AI 모드는 흰 옷 알파 255 유지, 모서리 알파 0 확인(통과). 같은 사진에 단색 모드는 부적합(설계상 로고·글자용). 머리카락 경계의 육안 비교는 미실시 |
| 속도 | 합의된 허용 시간 기준이 없었다. 위 실측값을 기준값으로 기록 |
| 안정성 | 5회 연속 실행·취소 시험은 미실시(취소 기능도 없음). **헤드리스 Edge에서 AI 모드 실행 시 탭이 충돌**(헤드리스 GPU/메모리 추정, 원인 미확정) — 그래서 E2E의 배경 제거는 단색 모드로 고정 |
| 프라이버시 | 코드상 이미지 픽셀은 워커 밖으로 나가지 않고 네트워크 요청은 가중치 `fetch`뿐. DevTools 네트워크 캡처 감사는 미실시 |
| 폴백 | WASM 경로 실행·측정 완료. WebGPU가 없는 브라우저(Firefox/Safari)에서의 자동 폴백은 미검증 |

**후처리 파라미터(확정값, `matting.ts`)**: guided filter 박스 반경 6·ε 2e-3(1024² 기준), 마스크 최종 알파 = `0.7·guided + 0.3·마스크`를 `[0.1, 0.9]`에서 펼침, 확정 배경/전경 밴드 0.01/0.99, blur-fusion 반경 10, 단색 모드 허용 오차 30·최소 대비 24. `01` §8에 같은 값을 기록했다. 단위 테스트 289개 통과(`matting.test.ts` 16개 포함).

**남은 리스크**: 헤드리스·저사양 환경, 대형 입력(메모리), Firefox/Safari에서의 AI 모드는 검증되지 않았다(§8 R-14).

### 3.4 CSP · 보안 검증

현재 `web/index.html` CSP:

`default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; connect-src 'self' blob: data: https://huggingface.co https://*.huggingface.co https://*.hf.co; worker-src 'self' blob:; font-src 'self' data:; object-src 'none'; base-uri 'self'; form-action 'self'`

| 변경 | 이유 | 결과 |
|---|---|---|
| `connect-src`에 `huggingface.co`, `*.huggingface.co`, `*.hf.co` | 모델 `fetch`(리다이렉트 CDN 포함) | 적용. Chromium 실측에서 다운로드 동작 |
| `script-src`에 `'wasm-unsafe-eval'` | onnxruntime-web WASM 인스턴스화 | 적용. Chromium에서 동작, 다른 브라우저는 미검증 |
| onnxruntime-web 자산 자가 호스팅 | `script-src 'self'` 유지 | WASM을 Vite `?url`로 번들에 포함(28.7MB, gzip 7.2MB). 가중치는 번들 밖 |
| COOP/COEP 헤더 | SharedArrayBuffer(WASM 멀티스레드) | `Cross-Origin-Opener-Policy: same-origin`, `Cross-Origin-Embedder-Policy: credentialless`를 vite dev/preview와 `vercel.json`에 추가. 모델 `fetch`는 `mode:'cors', credentials:'omit'`, 대표 이미지는 동일 출처 |
| 외부 사이트 링크 | 새 탭 이동 | `target="_blank" rel="noreferrer"`, CSP 영향 없음 |

원칙: 허용 호스트는 필요한 최소만, `'unsafe-eval'` 금지, `script-src` 외부 도메인 금지 — 지켜짐.

### 3.7 File System Access API 및 폴백

현 구현(`web/src/api/fsAccess.ts`): `showSaveFilePicker`/`showOpenFilePicker` 우선, 미지원/예외 시 `<a download>` + 숨김 `<input type=file data-dtf-picker>`; 사용자 취소(`AbortError`/`NotAllowedError`)는 null 반환; E2E용 `?dtf-e2e-download` 강제 플래그. 이미지 선택 필터는 `.png,.jpg,.jpeg,.webp,.bmp,.tif,.tiff,.psd`.

검증 상태: E2E(헤드리스 Edge)가 `.dtf` 저장(다운로드 캡처)과 열기 경로를 통과했다. 네이티브 픽커 저장 핸들 재사용, Firefox/Safari 폴백 동작, 다중 이미지 열기 폴백, 권한 거부·사설 모드는 **미검증**이다. 폴백 환경에서 "다운로드 폴더에 저장돼요" 같은 안내 문구는 구현하지 않았다.

## 6. 저장 방식 결정: 로컬 유지 vs 회원제

**결정(v0.5.0)**: 회원제 없음. 저장은 **IndexedDB 자동저장 + `.dtf` 파일**(로컬) 유지.

| 비교 | 로컬 유지 | 회원제(클라우드) |
|---|---|---|
| 개인정보 | 이미지가 브라우저 밖으로 나가지 않는다 — 제품의 핵심 신뢰 포인트 | 고객 도안(주문·인물 사진) 서버 저장 → 개인정보 처리·보관·삭제 책임 발생 |
| 비용·운영 | 정적 호스팅(`vercel.json`, `web/dist`)만으로 운영 | 인증·스토리지·백업·장애 대응·결제 필요 |
| 사용 진입 장벽 | 가입 없이 즉시 사용 | 가입·로그인 필요(비전문가 이탈 요인) |
| 대용량 | `.dtf`에 원본 내장(Base64)으로 이식 가능, 단 파일이 커짐 | 서버 저장으로 파일 이동 불필요 |
| 기기 간 동기화 | 불가(`.dtf` 수동 이동) | 가능 |
| 협업·공유 | 불가 | 가능 |
| 구현 복잡도 | 낮음(현 구조) | 높음 |
| 데스크톱 일관성 | `.dtf` 포맷이 동일 | 별도 동기화 설계 필요 |

로컬 유지 근거: (1) 사용자 이미지 비전송 원칙이 PRD 비기능 요구의 핵심, (2) 타깃(소규모 업체·셀러)의 즉시 사용성, (3) 현재 아키텍처가 이미 `.dtf` 이식(assets 내장)과 자동저장을 갖춤, (4) 운영 비용 0에 가까움.
로컬의 약점 보완(v0.5.0): 이어서 작업하기 카드는 구현했다. 명시적 저장 유도 문구(`04` §5.2)와 자동저장 상태 표시(`04` §3.4)는 구현하지 않았다(향후).
재검토 트리거: 기기 간 동기화/협업 요구가 반복 접수되거나, 사용자 인터뷰에서 "작업 소실" 사례가 다수 확인될 때(수치 기준은 정하지 않음).
