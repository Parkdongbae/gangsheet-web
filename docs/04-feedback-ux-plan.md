# 피드백·UX 인터랙션 기획서 (온보딩 · 피드백 · 재방문)

- **문서 목적**: 사용자가 "지금 무엇을 해야 하고, 방금 무슨 일이 있었고, 다음에 어떻게 되돌아오는지"를 알게 하는 안내·진행률·메시지·재방문 장치를 정의한다. (v0.5.0)
- **대상 독자**: 기획자, 디자이너, 프런트엔드 엔지니어, QA(문구 검수)
- **최종 수정일**: 2026-11-23 (v0.5.0)

> 이 도구는 생산성 도구라 점수·배지 같은 게이미피케이션은 맞지 않는다. 대신 **온보딩(처음 5분의 성공), 피드백(진행·성공·오류의 명확성), 재방문(작업 이어하기)** 3축으로 접근한다. **v0.5.0에서 구현한 것**: 시작 화면 3단계 안내, 빈 캔버스 안내, 배경 제거 단계 라벨, 이어서 작업하기 카드, 테마 토글, 단축키 다이얼로그. **구현하지 않은 것(향후)**: 첫 방문 코치마크(`dtf-onboarding-seen` 키 없음), 토스트 시스템, 최근 문서 목록, 드래그 오버 하이라이트, 자동저장 상태 표시, 표준 오류 문구. 오류는 여전히 `alert()`/`window.confirm()`이다(`App.tsx`, `ProxyCanvas.tsx`, `projectIO.ts`, `UpscaleDialog.tsx`, `webApi.ts`). 자동저장 복원의 `window.confirm`만 제거됐다.

원칙: ① 이미지는 브라우저 밖으로 나가지 않는다는 점을 **필요한 순간에** 알린다(현재는 시작 화면 하단 문구와 AI 설명 문단) ② 오류는 "원인 → 지금 할 일" 순으로(미구현, §4 표준안) ③ 기술 용어(DPI, pHYs, ONNX)는 가능한 한 감춘다 ④ `alert()`는 토스트/인라인 메시지로 대체한다(미구현, 향후).

## 1. 첫 방문 온보딩

### 1.1 시작 화면 3단계 안내 (정적, 구현됨)

시작 화면 히어로 하단에 항상 표시(`App.tsx STEPS`, `02` §2):

| 단계 | 제목 | 본문 |
|---|---|---|
| ① | 규격 고르기 | 필름 폭과 길이만 정하면 준비 끝 |
| ② | 이미지 올리기 | 끌어다 놓고 자동 배치로 빈틈없이 |
| ③ | 내보내기 | 인쇄소 규격 PSD · PNG · PDF로 저장 |

### 1.2 편집기 첫 진입 코치마크 — 미구현 (향후)

`localStorage['dtf-onboarding-seen']` 키와 3개 말풍선(이미지 추가 → 자동 배치 → 내보내기)은 구현하지 않았다. 대신 정적 장치 두 가지가 있다: 시작 화면 3단계 안내, 이미지 0개일 때의 빈 상태 안내(§2). 도입할 경우의 초안 문구는 "여기에 이미지를 끌어놓거나 눌러서 추가하세요. 이미지는 이 브라우저 안에서만 처리돼요." / "이미지를 시트에 빈틈없이 모아 줘요." / "다 됐으면 PSD·PNG·PDF로 내보내요. 해상도는 350 DPI로 맞춰져요."였다.

## 2. 빈 캔버스 드롭존 (구현됨)

- 조건: `images.length === 0`. 뷰포트 중앙 점선 박스(`02` §3.4).
- 문구: 제목 "이미지를 여기에 끌어다 놓으세요", 보조 "여러 장을 한꺼번에 올릴 수 있어요. 올린 뒤 자동 배치를 누르면 빈틈없이 정리됩니다.", 버튼 [이미지 선택], 형식 안내 "PNG · JPG · WebP · PSD".
- **미구현**: 드래그 오버 상태 강조, 비이미지 파일 드롭 안내, 추가 직후 페이드아웃, 박스의 `role="button"` 키보드 접근(버튼은 일반 `<button>`이라 키보드 선택은 가능).

## 3. 진행률 · 로딩 피드백

공통 원칙(목표): 작업 중에는 (a) 무엇을 하는지 한 줄, (b) 확정 가능하면 % 또는 n/N, (c) 취소 가능 여부를 보여준다. 현재 (a)(b)는 배경 제거·내보내기에서 구현됐고 (c) 취소는 내보내기·업스케일에만 있다.

### 3.1 AI 배경 제거 단계 (구현된 표시)

진행 표시는 속성 패널의 [배경 제거] 버튼 라벨이 바뀌는 방식이다(`PropertiesPanel.tsx bgStageLabel`, 워커의 `onRemoveBgProgress` 이벤트).

| 단계(`stage`) | 표시 문구 | 비고 |
|---|---|---|
| `download` | "AI 모델 받는 중 NN%" | 첫 사용 때만(Cache Storage 적중이면 건너뜀). % = 수신 바이트 / `Content-Length`(없으면 예상 크기 88.2MB·176.1MB) |
| `init` | "AI 준비 중…" | 세션 생성 |
| `infer` | "배경 분석 중…" | WebGPU 실패 후 WASM 재시도 때 한 번 더 나타날 수 있음 |
| `refine`, `encode` | "경계 다듬는 중…" | 두 단계가 같은 문구 |
| (이벤트 없음) | "처리 중…" | 단색 모드, 단계 시작 전 |
| 일괄 처리 | 문구 뒤 " (n/N)" | `removeProgress {current,total}` |

- 완료 시 선택 이미지가 즉시 갱신되고 별도 완료 안내(토스트)는 없다. 되돌리기는 Ctrl+Z.
- 실패는 모두 끝난 뒤 `alert("배경 제거 실패 n/N건: …")`로 한 번에 표시.
- **미구현**: 취소 버튼, WASM일 때 "느릴 수 있어요" 안내, 첫 사용 사전 확인 다이얼로그(모델 크기는 AI 설명 문단에 "약 85MB"로만 적혀 있음 — WebGPU fp16 약 84MB, WASM 폴백 fp32 약 168MB), 불확정 진행 막대, 다운로드 MB 표기.
- 실측 소요(1104×1428 JPG, 개발 PC): WebGPU 첫 실행 8.6초(다운로드 포함)·이후 1.6~1.7초/장, WASM(4스레드) 첫 실행 12.2초(다운로드 포함).

### 3.2 내보내기 (구현된 표시)

내보내기 다이얼로그(`ExportDialog.tsx`) 안에서 인라인으로 표시한다.

| 단계 | 표시 | 형태 |
|---|---|---|
| 항목 렌더 | "항목 렌더 7 / 12" (`stage:'items'`) | 스피너 + 텍스트 |
| 인코딩/저장 | "파일 저장 중…" (`stage:'write'`) | 스피너 + 텍스트 |
| 완료 | "완료 — W × H px · …" + 저장 경로 | 인라인(초록 체크) |
| 오류 | 오류 메시지 그대로(빨강) + [다시 시도] | 인라인 |

- 진행 중에는 Esc·바깥 클릭 닫기가 비활성이고 [취소]만 제공한다. 웹은 `내보내기가 취소되었습니다` 오류로 종료한 뒤 설정 단계로 돌아간다.
- **미구현**: 대형 문서(면적 > 2^28px) 사전 경고, 완료 토스트, [폴더 열기].

### 3.3 업스케일 / 프로젝트 열기·저장

- 업스케일: 기존 `UpscaleProgress`(`stage`, `step/totalSteps`, `overallProgress`)를 다이얼로그에 표시. 취소는 `window.confirm('업스케일을 취소할까요?')` 확인 후, 웹은 단계 사이에서만 반영.
- 프로젝트 열기·저장: 별도 진행 표시·성공 토스트는 없다(성공은 문서명 갱신으로만 드러남, 실패는 `alert`).

### 3.4 자동저장 표시 — 미구현 (향후)

상단 바에 "저장됨 방금 전" 같은 자동저장 상태 표시는 없다. 자동저장은 조용히 동작하고, 시작 화면의 "이어서 작업하기" 카드(§5)로만 드러난다. `kvSet`이 `false`(사설 모드)여도 사용자 경고는 없고 콘솔 경고만 남는다.

## 5. 자동저장 · 이어하기

### 5.1 규칙 (구현됨)

- 씬 변경 1.5초 후 IndexedDB 기록. 이미지 0개 씬은 기록하지 않음.
- 시작 화면 "이어서 작업하기" 카드(`App.tsx`, 시작 화면에 올 때마다 `window.api.getResumableSession()` 조회): 아이콘 + "이어서 작업하기" + "N분 전 자동 저장 · 이미지 N개 · W × H cm". 저장 시각은 상대 표기(방금 전 / N분 전 / N시간 전 / N일 전).
- 카드를 누르면 `openProject('web-autosave://last')`로 복원. 복원 후 문서명은 "자동 저장 문서". 실패 시 `alert`.
- 다중 탭: 마지막 기록이 이긴다(탭 잠금·안내 문구 없음).
- **미구현(향후)**: 카드의 [삭제] 링크, "새 문서를 시작하면 이전 작업이 대체돼요" 보조 문구(새 문서는 첫 이미지 추가 후 새 기록으로 덮어쓴다 — 이미지 0개 동안은 보존), 날짜 상세 표기.

### 5.2 명시적 저장 유도 — 미구현 (향후)

"브라우저를 바꾸거나 캐시를 지우면 작업이 사라져요. .dtf로 저장해 두세요" 같은 저장 유도 안내는 없다. 사실 관계만 정리하면: 자동저장은 이 브라우저에만 남고, 웹 `.dtf`는 원본을 내장하므로(`03` §1.4) 다른 컴퓨터에서도 열린다.

## 6. 테마

- 기본 밝게. 시작 화면 우상단(밝게/어둡게 두 칸 라디오)·편집기 상단 바 우측(아이콘 한 개)에 토글. 편집기 토글의 접근 라벨은 "어두운 화면으로 전환" / "밝은 화면으로 전환".
- 즉시 적용, 저장 `dtf-theme`. 캔버스·자·문서 테두리도 `useTheme()`로 즉시 재그리기(`02` §5).
- 시스템 다크 모드(`prefers-color-scheme`) 연동은 **구현하지 않았다**(향후: 최초 방문에 한해 OS 설정 따르기).

## 7. 단축키 도움말

- 진입: 상단 바 1행 우측 [단축키] 버튼만. `?` 키와 우클릭 메뉴 하단 항목은 **미구현**.
- 내용: 화면 보기 / 선택·이동 / 편집 / 정리·저장 4개 범주(`ShortcutsDialog.tsx`). Ctrl 표기만 있고 ⌘ 병기는 없다(코드는 `ctrlKey || metaKey` 양쪽 인식).
- 닫기: `Esc`, 바깥 클릭, [✕]. 열린 동안 캔버스 단축키 비활성.
- 하단 단축키 텍스트 벽은 제거됐고, 상태 바에는 정적 힌트 한 줄(휠 확대·축소 · Space+드래그 · 우클릭 메뉴, lg 이상)만 남았다. 이미지 선택 시 바뀌는 맥락 힌트는 미구현.

## 8. 마이크로 인터랙션

구현된 것: 버튼 눌림 축소(`active:scale-[0.98]`), 토글 `aria-pressed`, 스냅 가이드 `#22d3ee`, 잠금 테두리 `#f59e0b`. 아래 표의 나머지(드롭존 반응, 이동 애니메이션, 토스트, `prefers-reduced-motion` 처리 등)는 **향후 계획이며 구현되지 않았다**.

| 상황 | 인터랙션 | 시간/규칙 |
|---|---|---|
| 버튼 누름 | 눌림 축소(기존 `active:scale-[0.98]`) | 즉시 |
| 호버 | 배경 한 단계 변화, 툴팁(라벨+단축키) | 지연 400ms |
| 토글 켜짐(그리드·체커·Auto-Trim) | 배경 채움 + `aria-pressed=true` | 즉시 |
| 이미지 드롭 | 드롭존 반응 → 이미지 페이드인 | 150ms |
| 자동 배치 | 항목이 새 위치로 이동(애니메이션 선택) | 300ms 이내 — 빠른 PC에서 성능 확인, 문제 시 즉시 이동 |
| 스냅 | 가이드 라인 표시(기존 `#22d3ee`) | 드래그 중 |
| 배경 제거 완료 | 이미지에 짧은 하이라이트 + [되돌리기] 토스트 | 5초 후 사라짐 |
| 토스트 | 우하단 스택, 최대 3개, 성공 4초·오류는 닫기 전까지 | 호버 시 일시정지 |
| `prefers-reduced-motion` | 모든 이동·페이드 애니메이션 비활성 | 필수 |
| 진행 막대 | 확정형은 부드럽게 증가(점프 없음), 불확정형은 느린 이동 | — |

잠금/그룹 상태 변화에는 즉시 시각 단서(잠금 항목 선택 테두리 `#f59e0b` 기존 유지)와 토스트 없이 상태 바 항목 수 옆 아이콘만.
