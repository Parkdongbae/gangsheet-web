## 1. 배경과 문제

DTF GangSheet Studio는 DTF(Direct-to-Film) 전사 인쇄용 갱시트(여러 도안을 한 장의 필름 시트에 모아 배치한 인쇄 원판) 편집기다. 문서는 350 DPI 절대 픽셀 기준이며(`src/core/math/index.ts`), Electron 데스크톱 앱과 같은 React 렌더러(`src/renderer/src`)를 재사용하는 브라우저판(`web/`)이 있다.

### 1.1 불만 (오너 접수, v0.4.x 기준 — v0.5.0에서 대응)

| # | 불만 | 코드상 근거 | 사용자 영향 |
|---|---|---|---|
| P-1 | 어둡고 고밀도인 UI | `bg-zinc-950/900/800` 고정 다크, 밝은 테마 없음 | 비전문가가 낯설고 위압감, 낮 시간 작업장 가독성 저하 |
| P-2 | 글씨가 작음 | `text-[10px]`, `text-[11px]` 다수 (`App.tsx`, `ProxyCanvas.tsx` 오버레이) | 가독성·접근성 저하 |
| P-3 | 버튼 16개가 한 줄에 떠 있는 툴바 | `ProxyCanvas.tsx`의 `OverlayButton` 묶음(새 파일·열기·가져오기·트림·저장·복제·그리드 설정·체커·채우기·안에 맞춤·자동 배치·실행취소·다시실행·화면 맞춤·내보내기 등)이 캔버스 위 절대 위치 오버레이 | 무엇이 주 행동인지 모름, 아이콘만 있어 의미 불명 |
| P-4 | 하단 단축키 텍스트 벽 | 하단 좌측 오버레이에 단축키 문장이 한 덩어리로 나열 | 읽히지 않고 화면 면적만 차지 |
| P-5 | 시작 화면이 작은 다이얼로그 하나 | `App.tsx`: `w-[420px]` 카드 하나, 제품 설명·흐름 안내 없음 | 처음 온 사용자가 "무엇을 하는 도구인지" 모름 |
| P-6 | 웹 배경 제거가 AI가 아니었음 | v0.4.x `web/src/api/imageOps.ts`: 테두리 중앙값 색 + RGB 거리 32 플러드필 | 밝은 회색 배경 인물 사진에서 흰 옷이 배경으로 번져 뚫리고, 머리카락 경계가 거침 |

P-6의 원인(v0.4.x): 단색 플러드필만 있어서, 배경과 RGB 거리 32 이내인 흰 옷 픽셀이 테두리와 연결되면 함께 제거됐다. 경계는 이진(알파 0 또는 유지)이라 머리카락처럼 가는 경계에서 거칠었다. v0.5.0에서 AI 모드로 해소했다(F-4, 제보된 실패 사례의 재현 확인 결과는 AC-4.1).

## 2. 목표 / 비목표

### 2.1 목표 (v0.5.0)

1. **첫 화면 3초 이해**: 시작 화면만 보고 "규격 선택 → 이미지 올리기·자동 배치 → PSD/PNG/PDF 내보내기" 3단계를 이해한다.
2. **밝은 테마 기본**, 어두운 테마 선택 가능. 모든 화면에서 한 번 클릭으로 전환.
3. **정리된 편집기 UI**: 상단 2행 바(1행 문서·파일·실행취소·도움말·테마·내보내기, 2행 이미지 추가·배치·보기) + 얇은 하단 상태 바 + 속성 패널(폭 320px). 본문 최소 글씨 11px(예외: 자 모서리 라벨·"DTF 추천" 배지는 10px로 남아 있음).
4. **웹 배경 제거를 실사용 가능한 품질로**: 브라우저 안 AI(ISNet) 모드 + 개선된 단색 모드.
5. **개인정보 불변식 유지**: 사용자 이미지는 브라우저 밖으로 전송되지 않는다(모델 가중치만 내려받음).
6. 기존 워크플로(문서 크기 규칙, .dtf 호환, 단축키)를 **깨지 않는다**.

### 2.2 비목표

- 회원제·클라우드 저장·결제 (결정 근거: `docs/05-mvp-scope-poc.md` §6).
- 웹에서 CMYK PSD 생성 (lcms 불가 — RGB PSD 유지, 데스크톱 CMYK 유지).
- 세로 3m 이상 문서 (PSD 30,000px 한계, `.agent/CLAUDE.md` §1-3 절대 규칙).
- 웹 업스케일의 AI화 (v0.5.0은 리샘플 유지).
- 모바일 터치 편집 최적화 (보기·시작 화면 반응형까지만).

## 4. 핵심 시나리오

- **S-1 첫 방문 → 시트 완성**: 시작 화면 → A3 카드 선택 → [문서 만들기] → 빈 캔버스 드롭존에 이미지 5장 드롭 → [자동 배치] → [내보내기] PNG.
- **S-2 인물 사진 누끼**: 이미지 선택 → 속성 패널 "배경 제거" → "AI 자동"(첫 사용 시 모델 다운로드 진행률 %) → 결과 PNG(원본 치수) → "투명 배경 표시"(체커)로 경계 확인.
- **S-3 로고 단색 배경 제거**: 흰 배경 로고 → "단색 배경" → 안티앨리어싱 보존된 경계.
- **S-4 재방문 이어하기**: 브라우저 재시작 → 시작 화면 "이어서 작업하기" 카드 → 복원.
- **S-5 롤 시트 대량 배치**: 50cm × 2m 롤, 이미지 30장, 자동 배치(간격 2cm 기본) → 효율(%)·미배치 확인.
- **S-6 업체 전달**: .dtf 저장(원본 내장) 또는 PSD(웹 RGB, 데스크톱 CMYK) 내보내기.

## 5. 기능 요구사항

우선순위: **P0** = 릴리스 차단, **P1** = 릴리스 포함 목표, **P2** = 시간 허용 시.

### F-1 테마 시스템 (P0) (구현 완료)

- 밝은 테마가 기본값. `localStorage['dtf-theme'] = 'light' | 'dark'`(알 수 없는 값은 `light`). 시작 화면 우상단은 "밝게/어둡게" 두 칸 선택, 편집기 상단 바 우측은 아이콘 한 개 토글(`components/ThemeToggle.tsx`).
- 구현: `<html data-theme>` + Tailwind v4 색상 CSS 변수. 어두운 팔레트가 Tailwind 기본이고, `:root:not([data-theme='dark'])`일 때 `src/renderer/src/assets/main.css`가 `--color-zinc-*`를 뒤집어 재정의한다(기존 zinc 클래스 유지). 캔버스(문서 테두리)·자(ruler) 색은 `useSyncExternalStore` 기반 `useTheme()` 훅(`theme.ts`)으로 분기. 강조색 indigo 유지.
- **수용 기준**
  - AC-1.1 저장값 없으면 `light`로 렌더. `theme.ts`가 모듈 평가 시 동기로 `data-theme`을 설정하며(React 첫 렌더 전), `index.html`에 사전 설정 스크립트는 없다. 밝은 테마 사용자는 구조상 깜빡임이 없고, **어두운 테마를 저장한 사용자의 첫 페인트 깜빡임 여부는 미검증**.
  - AC-1.2 토글 즉시 전체 화면(캔버스·자·다이얼로그 포함) 전환, 새로고침 후 유지 — 구현됨. E2E 항목에는 없다.
  - AC-1.3 `localStorage` 접근 실패 시 `light`로 동작(읽기·쓰기 모두 `try/catch`).
  - AC-1.4 본문 대비 WCAG AA(4.5:1): **측정 도구로 확인하지 않음(미검증)**. indigo-300/400, amber, red, emerald 텍스트는 밝은 테마에서 진한 톤으로 재정의했다(`main.css`).

### F-2 시작 화면 (P0) (구현 완료)

- 전체 화면 랜딩(`App.tsx`). 좌측 히어로(제목·설명·대표 이미지·3단계 안내), 우측 열: 자동저장이 있으면 맨 위에 "이어서 작업하기" 카드(`window.confirm` 대체), 그 아래 "새 문서 만들기" 카드(롤/A4/A3 프리셋 카드, 롤 가로 폭 빠른 선택 30/50/60/100cm + 5~100cm 드롭다운, 세로 1m/2m, [문서 만들기] 기본 버튼, [프로젝트 열기 (.dtf)]), 상단 헤더 우측에 테마 전환.
- 대표 이미지: Canva에서 생성·내보내기 후 `src/renderer/src/assets/hero.webp`(1200×900, 47KB)로 번들에 포함(동일 출처).
- 기존 규칙 유지: 롤 가로 폭 5~100cm(1cm 스텝, 기본 50), 세로 1m/2m, A4 21×29.7cm, A3 29.7×42cm.
- **수용 기준**
  - AC-2.1 `lg`(1024px) 이상에서 2열, 미만에서 1열로 쌓임. "1280×720에서 스크롤 없이 모두 보임"은 **미검증**(페이지는 세로 스크롤 가능, `overflow-y-auto`).
  - AC-2.2 자동저장이 없으면 "이어서 작업하기" 카드 비표시, 있으면 "N분 전 자동 저장 · 이미지 N개 · W × H cm" 표기(`getResumableSession` 결과).
  - AC-2.3 이어하기에서 `window.confirm`을 쓰지 않는다 — 충족. 복원 실패 시에는 카드 내 오류 문구가 **아니라** `alert("프로젝트 열기 실패: …")`이다(인라인 오류는 미구현). 새 문서 진행은 가능.
  - AC-2.4 대표 이미지는 번들 에셋으로 외부 요청 없이 표시(CSP `img-src 'self'`) — 충족.

### F-3 편집기 상단 바 / 하단 상태 바 / 빈 상태 (P0) (구현 완료)

- 상단 바 1행(높이 56px): [로고·문서명(없으면 "제목 없음") .dtf] [새 파일 / 열기 / 저장] [실행취소 / 다시실행] … 우측 [단축키] [테마 토글] [내보내기(기본 강조)].
- 상단 바 2행(높이 48px): [이미지 추가(강조)] | 배치: [자동 배치][이미지 복제][채우기][안에 맞춤] | 보기: [그리드][투명 배경 표시][여백 자동 제거]. 각 버튼은 아이콘+텍스트 라벨이 항상 표시되고(아이콘만 축약하는 동작은 없음) 툴팁은 `title`/`aria-label`로 제공.
- 하단 상태 바(높이 40px): 문서 크기(cm, md 이상에서 px 병기), "이미지 N개", 조작 힌트 한 줄(lg 이상: 휠 확대·축소 / Space+드래그 / 우클릭 메뉴), 방향키 이동 거리 −/+ 스텝퍼(1~50mm, 기본 5mm), 배율 %, [화면 맞춤]. **줌 −/+ 버튼은 없다**(배율 표시와 화면 맞춤만, 줌은 마우스 휠).
- 하단 단축키 텍스트 벽은 삭제하고 "단축키" 다이얼로그(F-8)로 이동. 이미지 0개면 캔버스 중앙 빈 상태 안내("이미지를 여기에 끌어다 놓으세요", [이미지 선택], "PNG · JPG · WebP · PSD").
- 글씨: 본문 11px 이상. 예외로 `text-[10px]`가 두 곳 남아 있다(`RulerOverlay` 모서리 라벨, `BgSitesDialog`의 "DTF 추천" 배지). 속성 패널 폭 `w-80`(320px).
- **수용 기준**
  - AC-3.1 기존 모든 기능에 접근 경로 유지(우클릭 메뉴 포함) — 구현상 유지. 이 항목 전용 자동 테스트는 없고 기존 Vitest 범위만 통과.
  - AC-3.2 기존 단축키 전부 동작. 단, `?` 키로 도움말을 여는 진입은 없다(F-8).
  - AC-3.3 이미지 1개 추가 시 빈 상태 안내가 사라지고(`images.length === 0`일 때만 렌더), 모두 삭제하면 다시 나타난다.
  - AC-3.4 상단 바 각 행은 `overflow-x-auto` 한 줄이다. 좁은 폭에서는 줄바꿈 대신 가로 스크롤된다(그룹 단위 줄바꿈·드롭다운 접기는 미구현).

### F-4 배경 제거 — AI 자동 (웹) (P0) (구현 완료)

- 속성 패널의 "AI 자동 / 단색 배경" 모드 선택(`BgModePicker`, `window.api.bgRemovalModes = ['ai','solid']`일 때만 표시). 기본 "AI 자동", 마지막 선택은 `localStorage['dtf:bg-mode']`로 기억. 다중 선택이면 차례로 일괄 처리하고 전체를 Ctrl+Z 한 번으로 되돌린다.
- 브라우저 안에서 ISNet general-use(DIS) ONNX를 onnxruntime-web 1.31.1로 실행. WebGPU(`shader-f16` 지원 시, fp16 가중치 약 84MB) 우선, 불가·실패 시 WASM(fp32 가중치 약 168MB, `crossOriginIsolated`이면 최대 4스레드). Web Worker(`web/src/api/bgRemoval/bgWorker.ts`)에서 수행하며 세션은 재사용.
- 가중치: Hugging Face `imgly/isnet-general-onnx`(MIT), **리비전 고정 URL**로 첫 사용 시 내려받아 Cache Storage `dtf-bg-models-v1`에 보관. 가중치는 번들에 포함되지 않는다. 이미지는 서버로 전송되지 않는다(네트워크 요청은 가중치 다운로드뿐).
- 파이프라인(규칙 상세 `01-core-logic-spec.md` §8): 원본 → 1024×1024 리사이즈 → 정규화(v/255 − 0.5) → 추론 → 마스크 min-max 정규화 → 원본 해상도로 fast guided filter 업샘플(원본 휘도 가이드) → 알파 레벨 보정(≤0.1 → 0, ≥0.9 → 1) → blur-fusion 전경색 추정 디프린지 → 32-bit RGBA PNG(원본 치수 유지).
- 데스크톱은 기존 rembg(isnet-general-use) 사이드카 유지(`bgRemovalModes` 미정의 → 모드 선택 UI 없음).
- **수용 기준**
  - AC-4.1 흰 옷 + 밝은 회색 배경 인물: **충족(사용자 제보 사례 1건 수동 확인)** — AI 모드에서 흰 옷 알파 255 유지, 모서리 알파 0. 20장 샘플 세트 검수는 하지 않았다(`05` §7.2).
  - AC-4.2 결과 PNG 치수 = 입력 치수 — 원본 해상도 캔버스에 알파·색만 쓰는 구조라 치수가 유지된다. 치수 자동 검증 테스트는 없다.
  - AC-4.3 첫 사용 시 다운로드 진행률(%)은 표시("AI 모델 받는 중 NN%"). 두 번째부터는 코드상 `cache.match` 적중 시 다운로드 없음(새로고침 후 적중 시험 기록은 없음, 미검증). **취소 버튼은 없다**(미구현).
  - AC-4.4 WebGPU 불가 시 WASM 자동 폴백 — 충족(추론 중 WebGPU가 실패해도 한 번 WASM으로 재시도). "느릴 수 있음" 안내 문구는 **미구현**.
  - AC-4.5 외부 요청 감사: 코드상 이미지 픽셀은 워커 밖으로 나가지 않고 요청은 가중치 `fetch`뿐. DevTools 네트워크 캡처 감사 기록은 없음(미검증).
  - AC-4.6 모델 다운로드 실패 시 복구 행동: **전용 UI 없음**. 실패는 `alert("배경 제거 실패 …")`로 표시되며, "단색 배경" 전환과 "다른 배경 제거 사이트 보기" 진입은 속성 패널에 항상 있다. 피사체를 못 찾으면 오류 문구가 "단색 배경 방식을 사용해 보세요"를 안내한다.

### F-5 배경 제거 — 단색 배경 개선 (P1) (구현 완료)

- v0.4.x: 테두리 중앙값 색 추정 → 테두리 연결 유사색 플러드필(RGB 거리 32), 경계 1px 알파 ×0.6.
- v0.5.0: 허용 오차 RGB 거리 30, 알파 < 16은 배경 취급. 경계 2링을 5×5 이웃에서 가장 먼 색을 전경으로 보고 부분 알파 α = d/dMax와 배경색 역혼합으로 복원(`matting.ts removeSolidBackgroundPixels`). 전경과 배경 대비가 24 미만이면 경계 보정 생략.
- **수용 기준**: 흰 배경 + 안티앨리어싱 글자 로고에서 경계에 흰 헤일로가 없고 글자 내부의 흰색은 테두리와 연결되지 않으면 보존 — 연결 기반 플러드필이라 내부 보존은 구조적으로 성립하고, 헤일로 육안 검수는 **미실시**. 이 모드는 설계상 로고·글자용이며 사진(제보된 회색 배경 인물)에는 부적합하다.

### F-6 배경 제거 사이트 목록 갱신 (P1) (구현 완료)

- 순서: **Canva(배경 제거 도구, 맨 위)**, Adobe Express, Erase.bg, Photoroom, Clipdrop. **Remove.bg 삭제**. Canva·Adobe Express·Erase.bg에 "DTF 추천" 배지.
- 코드: `BgSitesDialog.tsx`의 `BG_REMOVAL_SITES`(5개). 다이얼로그 제목은 "배경 제거 사이트", 하단에 번들 가이드 PDF 2종 버튼.
- **수용 기준**: 목록 5개, Canva가 첫 항목, Remove.bg 문자열 제거 — 충족. 링크는 `target="_blank"` + `rel="noreferrer"`(`noreferrer`가 `noopener`를 함의).

### F-7 자동저장 / 이어하기 (P0, 기존 + 개선) (구현 완료)

- 씬 변경 1.5초 디바운스(`DEBOUNCE_MS = 1500`) → IndexedDB `kv['autosave-project']`. 빈 씬은 기록하지 않음.
- 부팅 시 `window.confirm`은 제거. 시작 화면이 `window.api.getResumableSession()`으로 조회해 "이어서 작업하기" 카드를 표시하고, 클릭하면 `openProject('web-autosave://last')`로 복원한다. 카드에 저장 시각(상대 표기)·이미지 개수·규격 표시.
- **수용 기준**: AC-7.1 이미지 추가 후 2초 내 새로고침 → 이어하기 카드 노출 → 복원. E2E(`web/e2e/web-e2e.mjs`)가 재로드 후 카드 복원을 통과한다(검증 신호는 "빈 씬이 아님·페이지 오류 없음"이며 그룹·잠금 동일성 자동 검증은 없음).

### F-8 단축키 도움말 (P1) (구현 완료, 일부 차이)

- 상단 바 1행 우측 [단축키] 버튼으로 여는 다이얼로그(`ShortcutsDialog.tsx`). 단축키를 화면 보기·선택/이동·편집·정리/저장 4개 범주로 정리. `Esc`·바깥 클릭으로 닫기.
- **`?` 키 진입은 구현하지 않았다**(향후). 범주 이름도 계획(선택·이동·편집·보기·파일)과 다르다.
- **수용 기준**: 기존 하단 텍스트의 단축키 수록 — 충족. 다만 Ctrl+Shift+G(그룹 해제), Ctrl+Shift+Z(다시실행), Backspace(삭제)는 도움말 표에 별도 표기가 없다.

### F-9 내보내기 (기존 유지, P0)

- PSD(웹 RGB / 데스크톱 CMYK, 350 DPI), PNG(pHYs 350 DPI), PDF(검수용 단일 페이지). 규칙은 `01-core-logic-spec.md` §7.
- v0.5.0 변경: 진행 표시는 기존 진행률 다이얼로그 유지. **오류 문구 표준화는 하지 않았다** — 오류는 여전히 `alert()`(`04` §4).

### F-10 이미지 투입 개선 (P2) (일부 구현)

- 빈 상태 안내에서 파일 선택([이미지 선택])·드롭 가능. 붙여넣기(Ctrl+V 이미지)는 **미구현**(Ctrl+V는 앱 내부 복사본 붙여넣기만). 드래그 오버 하이라이트도 미구현.
